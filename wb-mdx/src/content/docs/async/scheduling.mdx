The `#[Scheduled]` attribute runs a bean method on a recurring timer, with no external cron job. Scheduled tasks run in a **dedicated worker process**, separate from the HTTP workers, so a slow task never blocks request handling. Intervals are fixed (in seconds); cron expressions are not supported.

## Prerequisites

Scheduling needs the `swoole` extension and the `WinterWebSwooleApplication` runner; it is not available under PHP-FPM. See [Installation](/winter-boot/installation).

## Enable Scheduling on Your Application Class

Add `#[EnableScheduling]` to your `#[WinterBootApplication]` class. Without it, `#[Scheduled]` attributes are ignored. If the `swoole` extension is missing, startup fails with an `AnnotationException`.

```php title="MyApplication.php"
use dev\winterframework\stereotype\WinterBootApplication;
use dev\winterframework\stereotype\task\EnableScheduling;
use dev\winterframework\core\app\WinterWebSwooleApplication;

#[WinterBootApplication(
    configDirectory: [__DIR__ . '/config'],
    scanNamespaces: [['com\\example', __DIR__ . '/src']]
)]
#[EnableScheduling]
class MyApplication
{
    public static function main(): void
    {
        (new WinterWebSwooleApplication())->run(self::class);
    }
}
```

## The `#[Scheduled]` Attribute

Place `#[Scheduled]` on a `public`, non-final, non-abstract `void` method with no required arguments, on a `#[Service]` or `#[Component]` bean. Set exactly one interval — `fixedDelay`, `fixedRate`, or one of their `String` variants; setting none or more than one throws an `AnnotationException` at startup.

<Aside type="caution">
  All timing values are in **seconds** and must be positive.
</Aside>

### Parameters

- **`fixedDelay`** `int`
  Seconds to wait **after** the previous execution completes before starting the next. Use this when you want to avoid overlapping runs and the task duration may vary.

- **`fixedDelayString`** `string`
  Property placeholder (e.g. `${my.delay}`) that resolves to the `fixedDelay` value from your application configuration.

- **`fixedRate`** `int`
  Seconds between the **start** of successive executions, regardless of how long each run takes. Use this when you need a consistent heartbeat.

- **`fixedRateString`** `string`
  Property placeholder resolving to the `fixedRate` value from your application configuration.

- **`initialDelay`** `int`
  Seconds to wait after application startup before the first execution fires.

- **`initialDelayString`** `string`
  Property placeholder resolving to the `initialDelay` value from your application configuration.

## Fixed Delay vs. Fixed Rate

The two core scheduling modes behave differently when a task takes longer than its interval. Choose the one that matches your task's requirements.

<Tabs>
  <TabItem label="fixedDelay">
    `fixedDelay` introduces a gap between the **end** of one execution and the **start** of the next. Use this when you want to avoid overlapping runs and the task duration may vary.

    ```php title="CacheWarmer.php"
    use dev\winterframework\stereotype\Component;
    use dev\winterframework\task\scheduling\stereotype\Scheduled;

    #[Component]
    class CacheWarmer
    {
        #[Scheduled(fixedDelay: 60, initialDelay: 10)]
        public function refreshCache(): void
        {
            // Runs 10 seconds after startup, then again 60 seconds after
            // each completion.
            echo 'Cache refreshed at ' . date('H:i:s') . PHP_EOL;
        }
    }
    ```

    **Timeline:** `[startup] → 10s delay → run → 60s delay → run → 60s delay → run → …`
  </TabItem>
  <TabItem label="fixedRate">
    `fixedRate` fires the method every N seconds counted from the **start** of the previous invocation. Use this when you need a consistent heartbeat regardless of individual run time.

    ```php title="HealthReporter.php"
    use dev\winterframework\stereotype\Component;
    use dev\winterframework\task\scheduling\stereotype\Scheduled;

    #[Component]
    class HealthReporter
    {
        #[Scheduled(fixedRate: 30)]
        public function reportHealthMetrics(): void
        {
            // Fires every 30 seconds from the previous start time.
            echo 'Health check at ' . date('H:i:s') . ' — PID: ' . getmypid() . PHP_EOL;
        }
    }
    ```

    **Timeline:** `[startup] → run starts → 30s → run starts → 30s → run starts → …`
  </TabItem>
</Tabs>

## Configure Timing with Property Placeholders

Use the `String` variants of each parameter to read timing values from `application.yml`, so you can change schedules per environment without changing code.

```yaml title="application.yml"
app:
  scheduler:
    reportDelay: 45
```

```php title="SomeScheduler.php"
#[Component]
class SomeScheduler
{
    #[Scheduled(fixedDelayString: '${app.scheduler.reportDelay}', initialDelay: 5)]
    public function someScheduledMethodName(): void
    {
        echo 'Report generated: ' . uniqid() . PHP_EOL;
    }
}
```

<Aside type="tip">
  Combine placeholders with [fallback chains](/winter-boot/configuration#fallback-chains-with-) such as `reportDelay: "$env.REPORT_DELAY || 45"` to tune intervals per environment.
</Aside>

## Configuration

Configure the scheduling worker pool in `application.yml` under `winter.task.scheduling`:

```yaml title="application.yml"
winter:
  task:
    scheduling:
      poolSize: 1        # Number of scheduling worker processes (default 1)
      queueCapacity: 50  # Maximum number of scheduled tasks (default 50)
```

- **`poolSize`** `int` (default `1`)
  Number of worker processes that run scheduled tasks.
- **`queueCapacity`** `int` (default `50`)
  Maximum number of `#[Scheduled]` methods the scheduler can track.

<Aside type="note">
  With more than one application instance (for example several pods), every instance runs its own scheduler, so each task runs once **per instance**. Guard tasks that must run only once cluster-wide with a distributed [`#[Lockable]`](/winter-boot/ops/locking).
</Aside>

## Complete Example

The following files show a full scheduling setup: the application entry point and a scheduler component with two differently-timed tasks.

```php title="MyApplication.php"
use dev\winterframework\stereotype\WinterBootApplication;
use dev\winterframework\stereotype\task\EnableScheduling;
use dev\winterframework\core\app\WinterWebSwooleApplication;

#[WinterBootApplication(
    configDirectory: [__DIR__ . '/config'],
    scanNamespaces: [['com\\example', __DIR__ . '/src']]
)]
#[EnableScheduling]
class MyApplication
{
    public static function main(): void
    {
        (new WinterWebSwooleApplication())->run(self::class);
    }
}
```

```php title="SomeScheduler.php"
use dev\winterframework\stereotype\Component;
use dev\winterframework\stereotype\Autowired;
use dev\winterframework\task\scheduling\stereotype\Scheduled;

#[Component]
class SomeScheduler
{
    #[Autowired]
    private ReportRepository $reportRepository;

    /**
     * Generates a unique ID 10 seconds after startup,
     * then every 20 seconds after each completion.
     */
    #[Scheduled(fixedDelay: 20, initialDelay: 10)]
    public function someScheduledMethodName(): void
    {
        echo 'I generate a unique ID every 20 seconds: ' . uniqid();
    }

    /**
     * Persists a daily summary on a 24-hour fixed rate.
     */
    #[Scheduled(fixedRate: 86400, initialDelay: 60)]
    public function persistDailySummary(): void
    {
        $this->reportRepository->saveDailySummary(date('Y-m-d'));
    }
}
```
