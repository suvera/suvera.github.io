Winter Boot ships a small native extension, `winter_boot`, alongside the framework. It provides native AOP: aspect attributes and `#[Async]` methods work without any generated proxy classes. The extension is pre-installed and enabled in the Winter Boot runtime image.

<Aside type="note">
  Required since Winter Boot 2.1.0 — the application stops at boot when the extension is missing.
</Aside>

## Native AOP without proxies

Bean methods carrying aspect attributes (caching, transactions, custom aspects) and `#[Async]` methods are intercepted directly in the runtime — no subclass is generated, so `final` classes can carry advice too. (`final` *methods* are still rejected by attribute validation.) Nothing changes in application code: the same attributes, the same aspects, the same `begin`/`commit`/`failed` sequence. `#[Async]` calls still run in the background pool and return `null` to the caller; the queue records the real method name.

Behavior to be aware of:

- A value supplied through `stopExecution()` must match the method's declared return type exactly — a mismatch throws `TypeError` instead of being coerced.
- Aspect attributes on `static` methods are not supported (`TypeError`).
- An explicit `parent::` call to a method that itself carries advice runs that advice. Advice never fires for methods without attributes.
- On controllers, the dispatcher runs the advice of request-mapping endpoints directly (see [AOP on controllers](/winter-boot/core/aop#aop-on-controllers)).

## Building and installing

The extension source ships in the framework package (`vendor/suvera/winter-boot/php-ext/`). See [Installation](/winter-boot/installation) for build steps, and [PHP Extensions](/winter-boot/ops/extension-limits#winter_boot-required-since-210-native-capabilities) for known limits (JIT, Xdebug).
